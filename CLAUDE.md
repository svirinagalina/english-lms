# Advent Academy LMS

Galina's English-teaching platform. Production: **https://lms.advent-academy.online**, on server `srv3.advent-academy.online` (91.239.6.107), root SSH via `~/.ssh/lms_deploy`. Everything runs in Docker from `/opt/srv3/` (Caddy + app + Postgres). Repo: `svirinagalina/english-lms` (private, push over SSH).

## Stack
- `client/`: React 18 + Vite, plain CSS (`styles.css` + `styles/whiteboard.css`), React Router.
- `server/`: Node/Express (ESM), Prisma/PostgreSQL, Socket.io for the whiteboard and calls.
- Deploy: `git push` then `./deploy/deploy.sh` (builds, runs prisma migrate deploy, restarts the container, health-checks). Always commit with `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>` (or the model name the session shows).

## Local dev
- `psql english_lms` for the local Postgres DB (same schema as prod, different data).
- Client dev server: `npx vite --port 5199` inside `client/`. Server: `node --env-file=.env src/index.js` inside `server/` — **does not hot-reload**; restart it after any server-side edit before testing, or you'll silently test stale code (this has bitten me more than once this session).

## Architecture notes (read before touching these areas)

**Boards, one per student (redesigned 2026-09-20/21).** A student's cabinet shows exactly one board, given to them via **Assign** (a checklist of students on any board in "My boards" — checking a name attaches this board and detaches whatever that student had before, moving the old one back to the teacher's own shelf, never deleting it; a board can be checked for several students at once for pair/group lessons). There is no "Extra board" button anymore — `POST /classrooms/:id/boards` refuses to create a board directly in a student's classroom. `home` for a displaced board must be `ensurePersonalSpace(target.teacherId, ...)`, **not** the acting user's — I shipped a bug where an admin managing another teacher's student sent the displaced board to the admin's own shelf; fixed, but if you touch `assign` again, re-check this. A `Board.scratch` flag marks boards auto-created for a "call without a student" (colleague/group call); they're excluded from every board listing and deleted when that call ends (`signaling.js`, the 15-min-after-empty cleanup).

A board shared into a student (the normal post-Assign state: owned by the teacher's shelf, shared into the student via `sharedWith`) legitimately belongs to *two* classroom contexts at once. `GET /classrooms/boards` (`classrooms.js`) used to dedup its result globally by board id, so whichever classroom Prisma iterated first "won" and the other context's row vanished entirely — if the shelf's row won, the student's own call could never find the board (`Call.jsx`'s `boards.find(b => b.classroomId === call.classroomId)` came up empty: board doesn't display, no cursor/spotlight sync since the two sides end up on different boards, and vocabulary/mistakes misattributed). Fixed 2026-09-21: the endpoint now emits one row per (board, classroom) pair; `Controls.jsx`'s board picker dedupes by id for display, and `Call.jsx`'s `currentBoard` lookup prefers the row matching the call's classroom, then any row naming the board's actual student, before an unattributed one. Also closed the race that produced a literal duplicate `<name> — lessons` board: `GET /classrooms/:id`'s check-then-create and `assign`'s board moves now run under a `pg_advisory_xact_lock` keyed by the target classroom id.

**OCR on board images (2026-09-21).** Words inside a pasted screenshot or photo now get the same hover-translate/pronunciation and add-to-vocabulary treatment as real text — `wordUnderImagePoint` (`Whiteboard.jsx`) maps a point through the image's crop into its natural pixel space and looks it up in that image's `ocrWords()` result (`client/src/utils/ocr.js`, Tesseract.js). Recognition is cached per image `src` and starts on first hover — the first touch of a new image has a beat of latency, everything after is instant. Self-hosted under `public/tesseract` (`worker.min.js` + `core/` gitignored and rebuilt by `scripts/copy-tesseract.js` on every `prebuild`, matching how `@mediapipe/tasks-vision` is handled for blur; only `lang-data/eng.traineddata.gz` is committed, since there's no npm package to regenerate it from). A teacher's double-click on an image still opens crop mode as before — the OCR word-card only intercepts it for `wordPicker` (student) mode, and only when there's actually a word under the point.

**Pronunciation audio is the browser's speech synthesis, not the server's clip (2026-09-21).** `PlayButton` (`WordCard.jsx`) calls `speakAmerican` (`utils/speech.js`) first, which asks for a voice tagged exactly `en-US`; only falls back to the server's `/api/dictionary/audio` clip if the browser has no en-US voice at all. Reason: `dictionary.js`'s `translate_tts` call turned out to return byte-identical audio regardless of `tl` or which Google domain (`.com` vs `.co.uk`) it's requested from — verified by diffing the responses — so there was no way to make that endpoint specifically American. Don't try tweaking its `tl`/domain again for this; it doesn't respond to either. The IPA transcription (separate from the audio) was already American-first on both its sources and didn't need this.

**Spotlight follows, but doesn't fight a follower's own panning (2026-09-21).** `board:view` arrives up to 10/s while someone spotlights, and used to be applied unconditionally on every receiving client — a follower panning or zooming on their own board got snapped back within ~100ms, which is what "the board won't move" during a lesson turned out to be. `followPausedRef` (`Whiteboard.jsx`) now stops applying incoming `board:view` the moment a follower pans/zooms/pinches themselves (`pauseFollowing()`, called from every manual-navigation path — drag-pan, `zoomAround`, `movePinch`, the wheel handler's pan branch); a fresh `board:spotlight {on:true}` resets it, so the teacher can still pull everyone back to one place on demand. If you add a new way to move the view, call `pauseFollowing()` from it too or it'll silently be exempt from this. (`glideTo()` — New lesson/Homework's jump to the new heading — no longer animates at all, so it can't fight a manual pan the way it briefly could; see below.)

**`addHeading` (New lesson/Homework) doesn't move the view at all (2026-09-21).** First it animated there, then it jumped instantly, and Galina still called that "flying away" — the person clicking is already on the board, so any view change displaces them from whatever they were doing. It just adds the element now; nothing calls `glideTo` from that path any more. `glideTo` itself (instant, no animation — that part came first) still exists for `addBlock`, the one caller where a jump is actually correct: inserting a lesson summary's speaking questions from *outside* the board, where the person isn't already looking at it and does need the new content brought into view.

**`render()`'s per-element draw is wrapped in try/catch (2026-09-21).** Reported live as "the board disappears until reload" after New lesson/Homework — never reproduced under those exact steps, but the underlying risk was real and is now closed regardless: the draw loop over `elementsRef.current` had no error handling, so one element throwing (a stray NaN coordinate, a crop that no longer matches its image, a canvas hitting a browser's size limit at extreme zoom+pan on a huge image) left the canvas cleared for that frame and every one after — permanent until a reload got one fresh mount, and even then only until the same bad data threw again. Now each element's own try/catch logs and skips it instead. If this ever gets reported again, the browser console (`Failed to draw board element ...`) will name the element id/type responsible — check that first rather than re-guessing at reproduction steps.

**Noise removal and blur (`client/src/utils/noiseSuppressor.js`, `videoProcessor.js`).** Chain: browser filter → GTCRN neural denoiser (RNNoise fallback) → a custom "quiet-gate" AudioWorklet (−48/−54 dBFS) that was the fix that actually mattered — GTCRN alone left audible residue. Both sender and receiver denoise (VideoGrid denoises incoming audio too). Never awaited at join (plain mic first, swapped in when ready). Blur: mediapipe selfie segmenter; iPhone/iPad force the CPU delegate and the frame is copied to a canvas before compositing (Safari ignores `globalCompositeOperation` on a `<video>` source) — both were real bugs found via the `/api/diag` log, not guesswork. **Diagnostics are the fastest way to debug a "doesn't work for the student" report**: the browser POSTs to `/api/diag`, read with `docker logs ... | grep '\[diag\]'`; `blur.mask` events even carry a base64 thumbnail of what was actually composited. Trust this over guessing, and over the user's own uncertain description of what's wrong — but *do* trust the user's plain sensory report ("I can still hear the fan") over my own instrumentation if they conflict; that once turned out to mean the instrumentation was reading the wrong signal, not that the user was wrong.

**Exercise grading (`server/src/answerCheck.js`).** `checkAnswer()` is shared by grammar-unit exercises (`units.js`) and the mistake-notebook drill (`mistakes.js`) — a fix here covers both. Fixed 2026-09-21: a "no article needed" exercise stores its answer as an em dash `—`, which normalises to an empty string; the code used to reject any empty-normalised answer outright before comparing, so no student input could ever match. Lone `-`/`_` now normalise the same way `—` does (only when they stand alone as a "word" — `well-known` is untouched), and the empty-vs-empty case is judged like any other instead of short-circuited.

**Content quality (audit finished 2026-09-21).** `server/scripts/audit-exercise-content.js` checked every FILL_BLANK exercise (60/60 — the other 2291 exercises are TRANSLATE, which the script doesn't cover yet) and found 3 mismatches, written to `server/reports/exercise-audit.md` (gitignored, local only). Two were clear PDF-extraction corruption — imported as FILL_BLANK with no `__` in the prompt and an answer stripped of every space (`"Ihaveacar"`) — fixed by `server/scripts/fix-glued-translate-answers.js` (retyped as TRANSLATE with the answer respaced); verified this exact bug doesn't occur anywhere else in the book. Also fixed: 9 leftover "Т " drop-cap typos in theory text plus unit 4's run-on paragraph, via `server/scripts/fix-theory-typos.js` (a gap in `clean-book.js`'s T_WORDS list). Both scripts already ran against the JSON source and the local DB; **not yet run against production** — do that (append `DATABASE_URL=<prod-url>` per the script's own header) once Galina confirms. One item is still unresolved and needs her call, not an automated fix: chapter 2's "She __ the very girl I saw yesterday." (answer "the") — duplicate "the" after filling the blank, unclear whether the prompt or the answer key is wrong. Don't bulk-edit exercise content on a guess; it's Galina's paid curriculum.

**Vocabulary.** The personal set that words picked from the board/Writing land in is titled **"From my board"** (renamed from "My words" 2026-09-21 — if you ever see "My words" in code or copy, it's stale). `Study` (in `VocabSet.jsx`) supports `cram` mode — "Practice all cards", every card in deck order regardless of the spaced-repetition schedule, which deliberately never calls `reviewCard` so it can't disturb real due dates.

**UI panels.** Every cabinet list (My students, boards, invitations, etc.) is wrapped in `<Panel>` (`client/src/components/Panel.jsx`) — collapsible, remembers open/closed per browser via localStorage keyed by the `id` prop. When adding a new list to a page, wrap it in `Panel`, and make sure any "nothing here yet" empty-state text lives *inside* the panel, not floating above it (I've fixed this mistake twice already).

**Server hardening reminder:** every query must filter by `schoolId`; only OWNER/PARTNER (`isAdmin()`) cross school-internal teacher boundaries, and even then double-check who ends up owning any data that moves as a result (see the Assign bug above — the general pattern is "whose thing is this, not who clicked the button").
